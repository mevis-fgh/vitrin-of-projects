# АИС «Витрина ИТ-проектов»

Веб-приложение для организации взаимодействия студентов УУНиТ с ИТ-компаниями:
витрина кейсов, заявки, проектные команды, сопровождение выполнения, оценка результатов,
портфолио студентов, аналитика и администрирование.

Проект реализован по техническому заданию `Техническое_задание_Витрина_ИТ_проектов.pdf`
(ФГБОУ ВО «Уфимский университет науки и технологий», 2026).

**Технологии:** Python 3.10+ и только стандартная библиотека (без внешних зависимостей),
SQLite, серверный HTML/CSS. Один процесс, одна команда запуска — `python app.py`.

## Возможности

### Публичная часть (без входа)
- витрина ИТ-кейсов с поиском и фильтрами: направление, компания, сложность,
  формат участия, режим работы, тип вознаграждения, курс, наличие стажировки,
  сортировка по сроку и вознаграждению;
- карточка кейса: полное ТЗ, требования, критерии оценки, права на результат,
  отметка NDA, команда, результаты и победители;
- карточка компании: описание, отрасль, сайт, контакты, размещённые кейсы, показатели;
- витрина собственных проектов студентов с поиском;
- портфолио студента: компетенции, подтверждённые компаниями проекты, оценки,
  отзывы, призовые места, ссылки на GitHub/демо/презентацию;
- рейтинг студентов (завершённые проекты, средняя оценка, победы).

### Студент
- регистрация, вход, профиль с компетенциями и ссылками, смена пароля;
- подача заявки на кейс с сопроводительным письмом, портфолио и резюме;
- избранное, уведомления, приглашения от компаний;
- личный кабинет: статусы заявок, этапы, оценки, места, статус выплаты;
- команды, рабочая страница проекта (этапы, комментарии, файлы);
- отправка промежуточного и итогового результата (ссылка + файл);
- публикация собственных проектов в портфолио.

### Компания
- регистрация с прохождением модерации администратором;
- карточка компании;
- создание и редактирование кейсов, отправка на модерацию;
- обработка заявок: принять, отклонить, пригласить на собеседование;
- формирование проектной команды с ролями и наставником;
- рабочая страница проекта: контрольные точки, комментарии, файлы;
- оценка по 100-балльной шкале, отзыв, призовые места, статус выплаты;
- поиск студентов по компетенциям, курсу, институту и приглашение в проекты.

### Администратор
- модерация кейсов (опубликовать, отклонить, скрыть) и компаний (подтвердить, отклонить);
- управление пользователями: блокировка и восстановление доступа;
- сводная аналитика: пользователи, компании, кейсы, заявки, завершённые проекты,
  призовые фонды, распределение по направлениям и типам вознаграждения;
- отчёты с фильтром по периоду и экспорт в CSV и Excel (XLS);
- журнал действий (аудит) с фильтром по типу операции.

## Быстрый старт

### Windows
1. Установите [Python 3.10+](https://www.python.org/downloads/), при установке отметьте
   «Add Python to PATH».
2. Дважды нажмите **`START_WINDOWS.bat`**.
3. Браузер откроется на `http://127.0.0.1:8000`. Окно консоли не закрывайте.

### Linux / macOS
```bash
cd vitrina
./START_LINUX_MAC.sh          # или: python3 app.py
```

### Вручную (любая ОС)
```bash
cd vitrina
python app.py
# АИС «Витрина ИТ-проектов» 1.0.0
# Сервер запущен: http://127.0.0.1:8000
```

### Docker
```bash
docker compose up -d --build
# приложение: http://localhost:8000
```

База данных и загруженные файлы создаются автоматически при первом запуске
(`data.sqlite3` рядом с кодом либо в каталоге `DATA_DIR`).

## Как пользоваться

### Сквозной сценарий приёмки (как в ТЗ)
1. **Регистрация компании** → `/register` (тип «Компания»).
2. **Модерация компании** → администратор подтверждает компанию на `/dashboard`.
3. **Создание кейса** → «Новый кейс», заполнение карточки, отправка на модерацию.
4. **Публикация кейса** → администратор нажимает «Опубликовать».
5. **Поиск кейса студентом** → фильтры на главной странице.
6. **Подача заявки** → кнопка «Подать заявку» в карточке кейса.
7. **Принятие заявки** → компания на `/case/<id>/applications`.
8. **Формирование команды** → блок «Формирование команды» на той же странице.
9. **Выполнение проекта** → рабочая страница `/case/<id>/workspace`:
   этапы, комментарии, файлы.
10. **Загрузка результата** → студент отправляет ссылку и/или файл.
11. **Оценка компанией** → 0–100, отзыв, место, статус выплаты.
12. **Портфолио** → подтверждённый проект появляется в `/student/<id>` и `/rating`.

### Полезные адреса
| Адрес | Назначение |
|---|---|
| `/` | витрина кейсов |
| `/projects`, `/project/<id>` | проекты студентов |
| `/student/<id>` | портфолио студента |
| `/company/<id>` | карточка компании |
| `/rating` | рейтинг студентов |
| `/dashboard` | личный кабинет по роли |
| `/analytics` | аналитика и отчёты (администратор) |
| `/audit` | журнал действий (администратор) |
| `/healthz` | проверка работоспособности (JSON) |

## Настройки

Все параметры задаются переменными окружения (см. `.env.example`).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HOST` | `127.0.0.1` | адрес прослушивания; `0.0.0.0` — для Docker и хостингов |
| `PORT` | `8000` | порт |
| `DATA_DIR` | каталог проекта | где хранить базу и файлы |
| `DB_PATH` | `DATA_DIR/data.sqlite3` | путь к базе SQLite |
| `UPLOAD_DIR` | `DATA_DIR/uploads` | каталог загруженных файлов |
| `DEMO_MODE` | `1` | демонстрационные данные при пустой базе |
| `REGISTRATION_OPEN` | `1` | разрешить самостоятельную регистрацию |
| `ADMIN_USERNAME` | `admin` | логин первого администратора |
| `ADMIN_PASSWORD` | `Admin12345!` | пароль первого администратора |
| `ADMIN_EMAIL` | `admin@uust.ru` | e-mail администратора |
| `SESSION_TTL_HOURS` | `12` | время жизни сессии |
| `MAX_UPLOAD_MB` | `15` | максимальный размер файла |
| `COOKIE_SECURE` | `0` | `1` — передавать cookie только по HTTPS |

## Данные и резервное копирование

Вся система хранится в двух объектах:
- `data.sqlite3` — база данных (пользователи, кейсы, заявки, команды, этапы, журнал);
- `uploads/` — загруженные участниками файлы.

**Резервная копия** — остановить сервис (или использовать `sqlite3 .backup`) и скопировать
оба объекта:
```bash
sqlite3 /data/data.sqlite3 ".backup '/backup/vitrina-$(date +%F).sqlite3'"
tar czf /backup/uploads-$(date +%F).tar.gz -C /data uploads
```
Для требований ТЗ (бэкап не реже раза в сутки, хранение 30 суток) добавьте задание cron:

```cron
15 2 * * * sqlite3 /var/lib/vitrina/data.sqlite3 ".backup '/var/backups/vitrina-$(date +\%F).sqlite3'" && find /var/backups -name 'vitrina-*.sqlite3' -mtime +30 -delete
```

**Сброс демонстрационной базы:**
```bash
python app.py --reset-demo
```
или удалите `data.sqlite3` и запустите приложение снова.

## Развёртывание для всех пользователей

Кратко — четыре варианта, подробная пошаговая инструкция в
[`docs/DEPLOY.md`](docs/DEPLOY.md).

| Вариант | Кому подходит | Сложность | HTTPS и домен |
|---|---|---|---|
| Docker на VPS (Ubuntu) + Caddy/Nginx | постоянная работа, свой домен, соответствие 152-ФЗ | средняя | да |
| Render / Railway / Fly.io | быстрый показ заказчику, демо | низкая | да, автоматически |
| Российский облачный хостинг (Timeweb, Selectel, Yandex Cloud) | требования к размещению данных в РФ | средняя | да |
| Локальная сеть университета | демонстрация в аудитории | низкая | нет (HTTP в локальной сети) |

Минимальный сервер: 1 vCPU, 512 МБ RAM, 5 ГБ диска.

Важно для «боевого» запуска:
- поставить `DEMO_MODE=0` и задать `ADMIN_PASSWORD`;
- включить HTTPS (`COOKIE_SECURE=1`) через Caddy/Nginx/платформу;
- вынести `DATA_DIR` на постоянный диск и настроить резервное копирование;
- держать один процесс приложения (сессии и SQLite) — либо перейти на PostgreSQL
  при горизонтальном масштабировании.

## Безопасность

Реализовано:
- пароли хранятся как PBKDF2-HMAC-SHA256 с индивидуальной солью (120 000 итераций);
- сессии в базе данных, случайный идентификатор, cookie `HttpOnly` + `SameSite=Lax`,
  опционально `Secure`, ограничение времени жизни;
- CSRF-токен для всех форм авторизованных пользователей;
- ограничение попыток входа (10 неудач за 15 минут на логин и IP);
- разграничение доступа по ролям на каждом маршруте;
- экранирование пользовательского HTML, проверка внешних ссылок (только `http/https`);
- защита от обхода каталогов при отдаче статики и файлов;
- ограничение размера запроса и белый список расширений загружаемых файлов;
- журнал критических действий (вход, создание и изменение кейсов, заявки, блокировки);
- заголовки безопасности (`Content-Security-Policy`, `X-Frame-Options`,
  `X-Content-Type-Options`, `Referrer-Policy`).

Перед промышленной эксплуатацией дополнительно рекомендуется: корпоративный SSO
(ТЗ 4.3), защищённое резервное копирование, антивирусная проверка вложений,
внешний WAF и регламент обработки персональных данных (152-ФЗ).

## Ограничения и направления развития

Честно о том, что не входит в текущую версию:

- **PDF-экспорт**: отчёты выгружаются в CSV и Excel; PDF получается печатью
  страницы из браузера (стили `@media print` уже подготовлены).
- **E-mail и Telegram-уведомления**: сейчас только внутренние уведомления;
  архитектура готова к подключению SMTP/бота (функция `db.notify`).
- **Единая учётная запись университета (SSO/LDAP)**: не реализована, вход по
  логину и паролю.
- **Рекомендации** (ТЗ 5.18) — заявлены в ТЗ как перспективные.
- **Роль «Куратор/сотрудник УУНиТ»** — функции выполняет администратор.
- **Горизонтальное масштабирование** — SQLite и in-process сессии рассчитаны на
  один процесс; для нескольких узлов нужен PostgreSQL и общий кэш сессий.
